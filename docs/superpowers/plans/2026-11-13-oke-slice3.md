# OKe slice 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Several jobs and PMs at once, a derived user queue, an idle-only inbox delivered by `oke wait`, urgent findings through the inbox, and a per-repository merge line.

**Architecture:** All logic in `oke/bin/oke.py` (Python 3.6 stdlib), tested with the fake herdr. Skills carry the flow. The mod does not change.

**Spec:** `docs/superpowers/specs/2026-11-13-oke-slice3-design.md`

## Global Constraints

- Python 3.6, standard library only. No `time.time_ns`, no f-strings.
- No time-based liveness judgement. Times only order items.
- One writer per file. `state.json` changes go through `locked()`.
- Run `cd oke/bin && python -m unittest test_oke test_revive` green before every commit.

## Review Focus

- Two waits on one agent: only the newest reports or delivers.
- A delivery whose `herdr agent prompt` fails leaves the messages in the inbox.
- `--jobs` wait never returns the same PM report twice, and picks up a job created after it started.
- A PM API give-up never overwrites a final report of the current seq.
- `pending` deferral clears itself when seq or phase changes.
