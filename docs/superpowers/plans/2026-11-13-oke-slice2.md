# OKe Slice 2 Implementation Plan

> Executed natively (inline) in the session that wrote it; the user authorized autonomous execution through implementation.

**Goal:** Revive dead OKe agents automatically, retry API-error turns from inside each agent, and show a board pane in the orchestrator.

**Architecture:** `oke.py` gains `tick`, `revive`, `api-retry`, `resume-all` and board data; `oke wait` revives instead of reporting `gone`. A thin mod (`hooks/register.tsx`) calls `oke tick` every 10 s, retries API-error turns with backoff, and draws `/oke-board`.

**Tech Stack:** Python 3.6 stdlib, unittest with fake herdr; TypeScript mod on the Claude Code plugin API.

**Spec:** `docs/superpowers/specs/2026-11-13-oke-slice2-design.md`

## Global Constraints

- Python 3.6 standard library only; runs on Windows Git Bash and RHEL8 tcsh.
- No time-based liveness verdicts. The only time values: retry backoff `min(30 * 2^(n-1), 300)` s, stale lock 120 s, tick period 10 s.
- `api_retry_limit` default 20, from `config.json`.
- Revive gives up after 3 consecutive deaths; the count resets when the agent's `report.md` changed since the last revive.
- Files: `~/.oke/locks/<agent>`, `~/.oke/events.log`, `<agent folder>/api-retry.json`.

## Review Focus

1. A worker closed after merge must never be revived (final report present).
2. Two watchers (orchestrator mod and a PM's `oke wait`) racing on one dead agent revive it once.
3. `oke wait` must not return `idle_no_report` while the agent's mod is waiting to retry an API error.
4. A non-OKe session (role unknown) must get no retries and no ticks that change anything.
5. Orchestrator revival uses the recorded launch argv, not the PM's launch args.

## Tasks

### Task 1: revive core (`oke.py`)
- `should_be_alive(state, key, record, role) -> bool`, `revive(name) -> "revived" | "busy" | "gave_up" | "not_needed" | "unknown"`, lock helpers, events log, `oke revive <agent>`.
- `status --claim` records `orchestrator.argv` and `orchestrator.session` from `herdr pane process-info --pane <here>` and `agent get`.
- Tests: the spec's revive and alive-rule cases.

### Task 2: wait and tick
- `wait_loop`: on `gone`, call `revive`; keep waiting unless result is `gave_up` / `unknown` / `not_needed`. Treat `api-retry.json` in the report folder as busy.
- `oke tick --pane P [--board] [--events-from N]`: `{role, agent, revived: [...], events: [...], events_offset, board}`.
- `oke resume-all`.
- Tests: spec's tick and wait cases.

### Task 3: api-retry command
- `oke api-retry --pane P (--attempt N --error K | --clear | --give-up --error K)`; prints `{role, limit, folder}`.
- Tests: spec's api-retry cases.

### Task 4: mod
- `hooks/hooks.json` adds `"modules": ["./register.tsx"]`; `hooks/register.tsx`: python detection, tick timer (orchestrator/PM only), StopFailure + turn.complete retry with backoff, `/oke-board` pane with expand and focus, event toasts.
- `hooks/backoff.ts` pure function + `hooks/backoff.test.ts`.
- Verify: `claude plugin validate oke`, `claude plugin test oke`.

### Task 5: skills and command
- `commands/resume.md`; orchestrator skill: revival events, `gave_up`, deny path (6); PM skill: restart three-way rule (9), deny handling, `revive` instead of re-spawn.
- Docs: checklist additions for the company run.

### Task 6: live run
- Spec's four live checks on the toy repo. Fix what breaks (test first).
